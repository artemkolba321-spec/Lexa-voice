# Lexa — локальный мульти-инструмент

Ранний прототип персонального локального ассистента для Linux/Omarchy. Проект задуман как **tray-first приложение**: окно можно закрыть крестиком — оно скрывается в трей; контекстное меню трея позволяет открыть или завершить Lexa.

## Что уже есть

### Окно приложения

Окно фиксировано в портретном размере **480 × 860** логических пикселей. Изменение размера и разворачивание отключены в конфигурации Tauri; длинные страницы прокручиваются внутри окна. На узкой ширине боковая навигация открывается кнопкой меню.


- Tauri 2 + React + TypeScript + Rust.
- Тёмная панель: обзор, виртуальный умный дом, реестр инструментов, журнал и настройки.
- Rust-реестр с allowlist инструментов (`home.list_devices`, `home.get_state`, `home.set_power`, `home.set_temperature`, `system.get_status`).
- Песочница умного дома с виртуальными лампами, термостатом, розеткой и датчиком движения.
- Демо-команды на русском: «включи свет в гостиной», «выключи свет в спальне», «какая температура в спальне?», «поставь температуру в спальне на 22», «покажи устройства».
- Диапазон термостата ограничен 5–35 °C. Управление электрическими устройствами и системными процессами ОС пока не реализовано.
- Тесты ядра для управления разрешённым устройством и проверки диапазона температуры.
- Веб-режим без запуска Rust: демо можно оценить через Vite в браузере.

## Чего пока нет

Vosk, Qwen через llama.cpp, Silero TTS, wake word, постоянное прослушивание, память, автозапуск и настоящая интеграция с Home Assistant ещё **не подключены**. UI явно показывает, что голосовые компоненты не запущены. Демо-парсер — временная заглушка, а не языковая модель.

## Запуск в Omarchy / Arch Linux

### 1. Системные зависимости Tauri

```bash
sudo pacman -Syu
sudo pacman -S --needed \
  webkit2gtk-4.1 base-devel curl wget file openssl \
  appmenu-gtk-module libappindicator-gtk3 librsvg xdotool
```

Если в системе ещё нет Rust, установи `rustup` согласно официальной инструкции: https://www.rust-lang.org/tools/install. Нужны стабильный Rust toolchain и Node.js LTS.

### 2. Зависимости и режим разработки

В каталоге проекта:

```bash
npm install
npm run dev
```

Открой локальный URL Vite, который появится в терминале. В браузере будет работать демо-режим; трей доступен только в десктопной сборке.

Для запуска настоящего приложения Tauri:

```bash
npm run tauri dev
```

Первый запуск может скачать Rust-крейты и npm-пакеты. После установки пакетов UI и демонстрационная логика умного дома работают локально. У проекта нет обязательных запросов к облачному LLM API.

### 3. Тесты Rust

```bash
cd src-tauri
cargo test
```

## Архитектурные правила

1. **Модель выбирает инструмент, но не исполняет системные команды напрямую.** Все действия должны идти через реестр.
2. **Каждый инструмент — allowlist + валидация аргументов + разрешение.** Не добавлять универсальный `shell.exec` как инструмент по умолчанию.
3. **Виртуальный адаптер умного дома отделён от будущего Home Assistant-адаптера.** UI и команды не должны зависеть от конкретного производителя устройств.
4. **Профиль игры пока только состояние UI.** Он не отключает клавиатуру, не управляет Steam и не меняет устройства ввода.
5. Голосовой ввод должен иметь явный статус и физически заметный способ отключения; не путать «приложение запущено» с «микрофон слушает».

## Ориентировочный следующий порядок

1. Проверить запуск в Omarchy и поведение иконки в используемом Wayland/трей-окружении.
2. Перенести инструменты в отдельный модуль и описать manifest/schema/permissions для модов.
3. Подключить Vosk как отдельный локальный процесс и сделать явный статус микрофона.
4. Подключить llama.cpp через локальный endpoint и Qwen; сделать планирование вызовов инструментов с проверкой ядра.
5. Подключить Silero TTS и память на SQLite.
6. Реализовать Home Assistant-адаптер и только затем реальное управление устройствами.

## Лицензия

Пока не выбрана. Перед публикацией проекта стоит выбрать лицензию и проверить лицензии голосовых моделей и весов LLM отдельно от лицензии самого приложения.
